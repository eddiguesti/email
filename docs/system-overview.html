What LB-BOT Does

LB-BOT monitors the firm's email inboxes in real-time, automatically classifies each incoming email to the correct legal dossier (case file), and provides a dashboard for lawyers to review, approve, and manage these classifications.


Currently in read-only mode: the system analyzes emails but does not move, file, or send anything. It writes analysis results to the database so the dashboard shows real insights.

User Guide — What to Expect

Go to app.laurencebrosset-avocats.fr


You'll see the login page with the firm's branding. Click "Se connecter avec Microsoft".

After login, you're automatically redirected to the dashboard. Behind the scenes, the system also creates a Graph webhook subscription for your mailbox so new emails are monitored in real-time.

Step 5: Sender History

Navigate to Revue Pipeline → Expéditeurs.


Shows all known email senders and which dossier they're associated with. Each sender shows:

The system uses sender history as one of the 8 matching tiers. The more a sender is associated with a dossier, the more confident future matches become.

What Happens Automatically (No Action Needed)

  • Emails are monitored in real-time — The system watches your inbox via Microsoft Graph. You don't need to do anything.
  • Spam and newsletters are filtered — System emails, newsletters, and obvious spam are skipped automatically.
  • High-confidence matches are auto-classified — When the system is ≥85% confident, it classifies the email without asking.
  • Sender associations build over time — Each time you approve a match, the system learns and gets smarter.
  • Thread memory — Once a conversation is associated with a dossier, all future replies in that thread are automatically matched.
  • Graph subscription auto-renews — When you log in, the webhook subscription is refreshed automatically.

Current Mode: Read-Only

The system is currently in read-only mode. This means:


What it DOES:

  • Reads and analyzes incoming emails
  • Extracts legal references, entities, sender info
  • Matches emails to dossiers
  • Writes results to the dashboard database
  • Sends real-time notifications

What it does NOT do:

  • Move or modify emails in Outlook
  • Send any emails or replies
  • Create drafts in your mailbox
  • File documents to KLEOS
  • Delete or archive anything

When ready to go live, read-only mode can be disabled to enable auto-filing to KLEOS and draft generation.

Email Processing Pipeline

When a new email arrives in the monitored inbox, it goes through this pipeline:


Pipeline Stages
StageStatusWhat Happens
1. ReceiveRECEIVEDGraph webhook triggers, job queued to Service Bus
2. FetchFETCHING → FETCHEDFull email + attachments fetched from Graph API, PDFs text-extracted
3. ExtractEXTRACTING → EXTRACTEDRG numbers, entities, dates, sender domain, thread position extracted
4. MatchMATCHING → MATCHED8-tier matching engine finds the best dossier match
5. Skip FilterSKIPPEDNewsletters, spam, system emails filtered out automatically
6. ReviewREADY_FOR_REVIEWMatches with 60-85% confidence flagged for human review
7. File*FILED*Disabled in read-only mode* — would file to KLEOS
8. Draft*DONE*Disabled in read-only mode* — would generate reply drafts

8-Tier Matching Engine

Each email is matched to a dossier using up to 8 strategies, tried in order of reliability:


  • 1 Thread Memory — If this email thread was already matched, reuse that mapping Highest confidence
  • 2 RG Number Match — Extract legal reference numbers (RG/RPF) and match to dossier 95% confidence
  • 3 Sender Hints — Known sender-to-dossier associations from history
  • 4 Entity Overlap — Match named entities (people, companies, jurisdictions)
  • 5 Conversation Thread — Map based on conversation ID from prior matches
  • 6 Reference Exact — Exact dossier reference number in email body 95% confidence
  • 7 Sender History — Statistical sender-dossier correlation
  • 8 AI Classifier — xAI Grok model classifies based on content 90-97% confidence

Additional sub-tiers: KB Party Exact, KB Party Common, KB Party Fuzzy, KB Keyword, KLEOS Search

Deployment Commands

Web App (Vercel)

# Build shared package first
pnpm --filter @lb-bot/shared build

# Deploy to Vercel (workaround for turborepo)
mv turbo.json turbo.json.bak
vercel deploy --prod --force --yes
mv turbo.json.bak turbo.json

API (Azure Functions)

cd apps/api
node esbuild.config.mjs
zip -r /tmp/api-deploy.zip dist/ host.json package.json -x "*.map"
az functionapp deployment source config-zip \
  --name lb-bot-api --resource-group lb-bot-rg \
  --src /tmp/api-deploy.zip

Worker (Azure Functions)

cd apps/worker
node esbuild.config.mjs
# Include knowledge base in deployment
cp ../packages/shared/kleos-knowledge.json dist/
zip -r /tmp/worker-deploy.zip dist/ host.json package.json -x "*.map"
az functionapp deployment source config-zip \
  --name lb-bot-worker --resource-group lb-bot-rg \
  --src /tmp/worker-deploy.zip
